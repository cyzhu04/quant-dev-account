# Quant Dev Account｜量化开发学习主项目

从最小现金账户开始，逐步学习量化开发中的数据校验、交易记账、订单状态和自动化测试。

**当前范围：现金 + 单标的持仓 + 买卖手续费。**
这不是赚钱策略、完整回测框架或实盘交易系统，也不会连接券商、网络或真实账户。

初始账本实现、演示和测试使用 AI 辅助生成与校验。后续通过实际的代码修改、测试和开发记录推进学习，不把起步原型等同于从零独立开发完整交易系统。

## 1. 环境与运行

- Python 3.10 或更新版本。
- 仅使用 Python 标准库，不需要 pip 安装依赖。
- 下载或克隆仓库后，进入包含本说明的项目根目录，再执行下列命令。

```shell
python -m quant_account
python -m unittest discover -s tests -v
```

Windows 如果使用 Python Launcher，可将上述 `python` 替换为 `py -3`；macOS/Linux 如果命令名为 `python3`，则替换为 `python3`。请确保实际使用的解释器版本不低于 3.10。

第一条命令演示交易，第二条命令运行自动测试。测试失败时会返回非零退出码。

## 2. 最小用法

```python
from quant_account import CashAccount

account = CashAccount(initial_cash="10000.00", symbol="DEMO")

buy = account.buy(quantity=10, price="100.00", fee="1.00")
assert str(account.cash) == "8999.00"
assert account.position == 10

state = account.snapshot(mark_price="110.00")
assert str(state.market_value) == "1100.00"
assert str(state.equity) == "10099.00"

sell = account.sell(quantity=10, price="110.00", fee="1.00")
assert str(account.cash) == "10098.00"
assert account.position == 0
assert str(account.total_fees) == "2.00"
assert len(account.trades) == 2
```

`buy` / `sell` 返回本笔已完成交易的只读记录；账户的 `trades` 返回不可变的历史副本。
`snapshot` 用外部给定的价格估值，不会产生交易或改变账户。

## 3. 手算对照

| 步骤 | 现金 | 持仓 | 估值价 | 持仓市值 | 权益 | 累计手续费 |
|---|---:|---:|---:|---:|---:|---:|
| 初始 | 10000.00 | 0 | 100.00 | 0.00 | 10000.00 | 0.00 |
| 100元买10份，手续费1元 | 8999.00 | 10 | 100.00 | 1000.00 | 9999.00 | 1.00 |
| 估值价升至110元 | 8999.00 | 10 | 110.00 | 1100.00 | 10099.00 | 1.00 |
| 110元卖10份，手续费1元 | 10098.00 | 0 | 110.00 | 0.00 | 10098.00 | 2.00 |

账本规则：

- 买入后现金 = 原现金 − 数量 × 成交价 − 手续费。
- 卖出后现金 = 原现金 + 数量 × 成交价 − 手续费。
- 账户权益 = 现金 + 持仓数量 × 估值价。
- 最终全部平仓后，相对初始现金增加98元，即 `(110 − 100) × 10 − 1 − 1`。
- 未卖出时权益会随估值变化，但现金不会因此增加；不能把浮动收益当作现金。

## 4. 金额与交易约束

- 单标的、单币种、整数份额，只做多，不融资、不做空。
- 金额输入只能是字符串、Python整数或 `Decimal`。请传 `"100.00"`，不要传浮点数 `100.0`。
- 内部以整数“分”计算，对外返回 `Decimal`；不会发生二进制浮点累计误差，也不依赖 Decimal 全局运算精度。
- 价格、费用、初始现金都必须精确到分；`"1.000"` 可以，`"1.001"` 不可以。分以下非零金额直接拒绝，不偷偷舍入。
- 成交价必须大于零；估值价可以为零。现金和手续费允许为零，不能为负。
- `quantity` 必须是 Python正整数，不能是布尔值或 `1.0`；没有实现真实市场的整手限制。
- 每笔交易必须显式传 `fee`，它是**该笔固定费用金额，不是百分比**，无费用也要写 `fee="0.00"`。
- 费用在成交时一次扣除。卖出费用可使用已有现金支付，但交易后现金不能为负。
- 所有业务校验先于状态修改；校验失败时现金、持仓、累计费用、成交记录和编号均不改变。
- `InsufficientCashError` 表示现金不足；`InsufficientPositionError` 表示超卖。其他非法值抛 `ValueError`，不支持的类型抛 `TypeError`。

本版按公开方法顺序调用设计，不提供并发交易或数据库事务保证。

## 5. 代码怎么读

建议先阅读测试中的手算案例，再阅读账户实现，最后运行演示。

- [账户实现](<quant_account/account.py>)：金额校验、只读交易记录、账户买卖和估值。
- [演示入口](<quant_account/__main__.py>)：完整买入、估值、卖出和拒单后不变的示例。
- [自动测试](<tests/test_account.py>)：手算对照、异常、精度、只读记录及固定种子的交易序列检验。
- [公共接口](<quant_account/__init__.py>)：定义允许从包顶层导入的类。

不需要先理解所有辅助函数。第一轮先看 `CashAccount.buy`、`sell`、`_execute` 和 `snapshot`，回答：

1. 为什么买入时除了价款，还要检查手续费？
2. 为什么卖出前必须检查持仓？
3. 为什么生成估值快照不能改变现金？
4. 为什么校验失败不能留下一半更新的状态？

## 6. 测试覆盖的重点

- 从10000元开始的完整买卖和部分卖出。
- 多次买入、零费用、刚好用尽现金、零初始现金。
- 小数精度、较大金额、低 Decimal 精度下记账不变。
- 现金不足、超卖、负数、零数量、分以下金额、NaN、Infinity和错误类型。
- 失败交易不改账、不消耗成交编号。
- 估值和历史记录只读。
- 同一组固定种子的200次交易请求重复执行两遍，与独立的 Decimal 参考账本逐步核对，并比较最终成交历史。

测试提供的是这些场景下的正确性证据，不是适用于所有交易机制的证明。

## 7. 这一版故意不做什么

没有实现行情读取、信号、订单生命周期、撮合、滑点、费率/最低佣金模型、税费、分红拆分、平均成本、已实现/未实现盈亏拆分、数据库或实盘接口。

**`buy` / `sell` 的意思是“按已经确定的成交价记账”，不是“提交订单等待成交”。**
以后应由模拟券商决定成交价格、数量、费用，再调用本账户；策略不能直接修改账户。
本版的成交记录没有时间字段，调用顺序由连续编号表示，后续接入事件时再增加时间戳。

下一步可以增加“订单提交、成交、拒绝”这一层，但先保持本账户的测试全部通过。
